# Code of Conduct

## The short version

Be straightforward and be kind. Assume the person you are replying to is competent and acting
in good faith, because they almost always are.

## What is expected

- **Criticise the work, not the person.** "This breaks on Windows because the hook runs in a
  minimal shell" is useful. "Whoever wrote this clearly does not use Windows" is the same
  information with the useful part removed.
- **Say what you mean.** Directness is welcome here. A blunt, specific bug report is a
  contribution; a vague, polite one is work for someone else.
- **Accept that "no" is a complete answer.** Not every proposal fits, and a maintainer
  declining something is not an invitation to relitigate it.
- **Assume less context than you have.** People arrive mid-conversation, in a second language,
  at the end of a long day.

## What is not

Harassment, personal attacks, demeaning comments, unwelcome attention, publishing private
information, and sustained disruption after being asked to stop.

Also: hostility dressed as technical rigour. "Just being honest" does not cover contempt, and
a project where people are afraid to ask a naive question loses far more than it gains.

## Scope

Issues, pull requests, discussions, commit messages, and any space where you are representing
this project.

## Enforcement

Report to **motivated.naveen.sharma@gmail.com**. Reports are handled privately and the
reporter's identity is not shared without their agreement.

Responses range from a private word to a permanent ban, proportionate to what happened and
whether it continued after being raised. There is no appeals committee — this is a small
project, and the maintainer decides.

## Attribution

Adapted in spirit from the [Contributor Covenant](https://www.contributor-covenant.org/),
shortened deliberately. A code of conduct nobody reads protects nobody.
